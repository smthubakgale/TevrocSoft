Tevroc SDK: Build scalable Tevroc apps with JavaScript

A structured developer guide for installing Tevroc SDK, creating the client, and using auth, entities, integrations, and offline support across browser and native apps.

Welcome to the Tevroc SDK learning path. In this chapter, you will discover how a single JavaScript client can power auth, data, payments, files, integrations, and offline-first behavior across web and native apps. Getting started

The first chapter is about setting up your environment. Install the SDK, choose a runtime, and prepare the link between your app and the Tevroc worker. This is the foundation for every real-world feature you will build.

Choose the installation path that matches your project: modern web apps should prefer npm/ESM, while quick prototypes or static pages can use the browser script bundle. Either approach delivers the same runtime API surface.

Install the SDK

npm / ESM

npm install tevrocsdk

Use this in your React, Vue, Svelte, or native hybrid app to import the SDK as a standard module.

Browser

<script src="https://unpkg.com/tevrocsdk@latest/tevroc-sdk.min.js"></script>

Add this script tag directly to a static page or webview for fast testing without a build step.

Installation and setup

In this section you will make the SDK available to your app. Whether you choose npm for a modern JavaScript project or a browser bundle for quick prototypes, the install step unlocks the same Tevroc APIs across platforms.

If you are working on the Tevroc SDK repository itself, the local install path lets your application consume the SDK source directly while you iterate. For production apps, install the published npm package or deploy the compiled bundle from your build process.

Example: local package install

npm install ../tevrocsdk
cd ../tevrocsdk && npm run build

Use this flow when your app and SDK source are in the same workspace. After building, point your app import to the generated SDK files or publish the package to your private registry.

Create a client

This is the moment your app becomes Tevroc-aware. The client wires your runtime to Tevroc services and shares app identity, base URLs, and environment details. Treat it as the central control plane for everything you build next.

The client configuration tells Tevroc where your APIs are hosted and how to label requests in logs and dashboards. That means authentication, entity access, file URLs, and integrations all use the same shared runtime context.

import { createClient } from "tevrocsdk";

const tevroc = createClient({
  baseUrl: "https://your-worker.example.workers.dev", // worker entry point for Tevroc API calls
  serviceUrl: "https://services.example.com",      // service host for integrations and app services
  appId: "tevroc-portal",                         // your application identifier
  appName: "Tevroc Portal",                       // human-friendly name for logs and UI
});

You can also reuse an existing token from storage to keep users signed in across refreshes. If your app supports multiple environments, switch these values based on development, staging, or production configuration.

Authentication

Users expect secure sign-in and seamless identity handling. In this chapter, you will learn how Tevroc manages login, registration, password resets, and social sign-in while keeping your UX fast and reliable.

A good auth flow balances security and speed: prompt users only when necessary, preserve session state, and handle errors without blocking the experience. Tevroc helps you build that by exposing simple auth methods and session helpers.

Authentication flow

Sign in and profile

const { token, user } = await tevroc.auth.login({
  email: "ada@example.com",
  password: "correct horse battery staple",
});

const me = await tevroc.auth.me();

// Save token in secure storage and use `me` to render the signed-in user.

The login call returns both the current user and a fresh token. Use `tevroc.auth.me()` to validate the session and fetch profile details after page refresh.

Register, logout and reset

await tevroc.auth.register({
  email: "ada@example.com",
  password: "correct horse battery staple",
});

await tevroc.auth.logout();
await tevroc.auth.resetPassword({ email: "ada@example.com" });

// Handle responses and show helpful feedback for each auth step.

Use registration to create new users, logout to clear the current session, and reset password for recovery flows. Provide clear success and error messages for each action.

Google sign-in

await tevroc.auth.googleLogin({
  appId: "tevroc-portal",
  appName: "Tevroc Portal",
  serviceUrl: "https://services.example.com",
});

// OAuth providers can be added with minimal extra code.

Google login is a fast way to let users authenticate without managing passwords. Tevroc supports provider-based social auth alongside traditional email/password flows.

Work with entities

Entities are the backbone of your app’s data model. Learn how to create, query, update, and delete records, and how entity services help you build dashboards, lists, and workflows with consistent APIs.

With Tevroc entities, your data access patterns remain intuitive and repeatable. Each entity service exposes a predictable set of CRUD and query methods so you can build features without learning dozens of custom endpoints.

Entity architecture

Loading entities diagram...
const created = await tevroc.entities.Project.create({
  name: "Launch site",
  status: "active",
});

const projects = await tevroc.entities.Project.list({ limit: 20 });

const filtered = await tevroc.entities.Project.query({
  filter: { status: "active" },
  limit: 10,
});

await tevroc.entities.Project.update(created.data.id, { status: "done" });

// Use entity results for tables, dashboards, or summary cards.

The response objects are designed to include both record data and metadata, making pagination and filtering easier to implement in UI components.

Common entity methods

  • list() — fetch a page of records.
  • get(id) — retrieve a single record by its ID.
  • create(record) — save new data.
  • update(id, patch) — patch existing records.
  • delete(id) — remove a record.
  • query({ filter }) — run filtered searches.

Bulk and sync helpers

  • bulkCreate(records) — create many records in one request.
  • bulkUpdate(records) — update multiple records together.
  • bulkDelete(ids) — remove many records at once.
  • import(records) — ingest external data into the entity store.

Call custom functions

Think of custom functions as event-driven actions that run on Tevroc servers. In this section, you’ll see how to trigger logic like notification delivery, data transforms, or automation without hardwiring REST endpoints.

Custom functions are ideal for isolated business logic that doesn’t belong in the client. Use them to keep sensitive code on the server, to integrate with external systems, and to orchestrate multi-step workflows.

Invoke a function

await tevroc.functions.invoke("ping", { hello: "world" });

// Shorthand helper
await tevroc.functions.ping({ hello: "world" });

The first call uses a generic `invoke` method; the second is a convenience shorthand for the same operation. Both let you pass payload data to the server-side function.

Use core integrations

This chapter shows how Tevroc connects your app to external services and smart features. Add AI generation, email, uploads, and signed URLs quickly while keeping your code concise and reusable.

Core integrations let you build rich experiences without coupling each service directly into your frontend. Use Tevroc as the integration layer so your app stays light and the service configuration stays centralized.

Example integration calls

await tevroc.integrations.Core.InvokeLLM({
  prompt: "Write a two-line launch checklist.",
});

await tevroc.integrations.Core.GenerateImage({
  prompt: "A futuristic dashboard",
});

await tevroc.integrations.Core.SendEmail({
  to: "ada@example.com",
  subject: "Hello",
  text: "From Tevroc",
});

await tevroc.integrations.Core.UploadFile(file, {
  filename: "report.pdf",
  contentType: "application/pdf",
});

These integration methods let you request AI output, send email, or upload files with a single SDK call. The same pattern scales to additional connectors and custom integration adapters.

Accept payments

Monetization is often the next step after core app features. This section teaches you to add checkout creation, status listeners, and payment lifecycle handling while preserving a clear user flow.

Payment processing should be transparent to users: they need confirmation of success, a clear failure path, and a clean retry experience. Tevroc handles the checkout orchestration while your app focuses on the customer flow.

Create a checkout

await tevroc.payments.create({
  amountZAR: 50,
  appId: "tevroc-portal",
  mode: "web",
});

const unsubscribe = tevroc.payments.onstatus((status, error) => {
  if (error) {
    console.error("Payment listener error", error);
    return;
  }
  console.log("Payment status:", status);
});

Use `onstatus` to observe checkout progress and trigger UI updates. This keeps your payment flow responsive while the backend handles authorization, confirmation, and receipts.

Work with files and app data

Files and app state are essential for real apps. Here you’ll learn how to store and retrieve documents, images, and settings in a way that works across browser, mobile, and desktop shells.

Tevroc provides helpers for public URLs, private downloads, and native storage so that your file experience remains consistent across platforms. Use the same SDK calls in your web UI and in a mobile native container.

File helpers

const fileUrl = tevroc.files.url("reports/summary.pdf");
const privateFileUrl = tevroc.files.privateUrl("reports/private.pdf");
await tevroc.files.get("reports/summary.pdf");
await tevroc.files.getPrivate("reports/private.pdf");

Use `url()` for public assets and `privateUrl()` for signed access. The SDK also supports secure fetches of protected content through `getPrivate()`.

Native store helpers

const store = tevroc.native.store;
const ref = store.ref("settings");
await store.set(ref, { theme: "dark" });
await store.update(ref, { lastOpened: Date.now() });
await store.get(ref);
await store.remove(ref);

The native store lets you persist app state, preferences, and offline caches on the device. This works nicely with offline sync for a seamless native experience.

Offline and sync support

A great app stays useful when the network drops. In this section, you will see how Tevroc keeps data synchronized, caches updates locally, and recovers cleanly when connectivity returns.

Offline support is critical for mobile and field-first applications. Tevroc’s sync layer helps you queue changes locally, detect conflicts, and replay updates as soon as the device regains connectivity.

Sync example

const client = createClient({ baseUrl: 'https://api.example', appId: 'myapp' });
client.offline.startAutoSync();

client.offline.on('conflict', ({ conflictId }) => {
  console.warn('Conflict detected:', conflictId);
});

Start auto-sync early so cached writes and read operations stay aligned with the latest remote state. Add conflict handlers to surface merge decisions or automatic reconciliation.

Handle errors

Reliability is built by handling failure cases gracefully. This section shows how Tevroc surfaces structured errors so your app can recover from auth, network, and data issues cleanly.

Instead of letting exceptions break the UI, trap them and decide whether to retry, prompt for login, or show contextual help. Tevroc errors include status codes and structured payloads that make this straightforward.

Error handling example

import { TevrocError } from "tevrocsdk";

try {
  await tevroc.auth.me();
} catch (error) {
  if (error instanceof TevrocError && error.status === 401) {
    // Ask the user to sign in again.
  } else {
    console.error("Unexpected Tevroc error", error);
  }
}

Use `TevrocError` to distinguish SDK-specific failures from other runtime exceptions. This keeps your error handling targeted and your UX consistent.
